NES CPU를 LLM 가중치에 컴파일한 nesformer, 설치 없이 받아서 돌려 봤다

2026년 11월 1일 · 읽는 데 5분
한 줄 요약FC(게임기)의 CPU를 대형 언어모델의 가중치 안에 "번역"해, 모델을 돌리기만 해도 게임이 실행되게 만든 프로젝트다. 나는 저장소를 내려받아 아무것도 설치하지 않고 인터넷도 끊은 채로, 돌릴 수 있는 부분만 돌려 봤다.
▶
60초 영상으로 보기유튜브 커밋 한 모금 쇼츠

무엇인가

nesformer는 FC(게임기)의 6502 CPU와 2KB 워킹 RAM, 카트리지 프로그램을 표준 Qwen3.5 언어모델의 가중치 안에 그대로 담은 프로젝트다. 여기서 "컴파일"은 흔히 아는 컴파일러와 뜻이 다르다. 이 가중치는 누가 학습시킨 것이 아니라 컴파일러가 계산해서 만들었다.

핵심은 모델 내부의 "상태"를 기계의 메모리로 쓰는 것이다. 언어모델은 입력을 읽으면서 기억 공간을 계속 갱신한다. 프로젝트에서는 이 구조를 Gated DeltaNet이라 부르는데, 여기를 6502의 메모리로 쓴다. 메모리 주소를 "하나만 켜는 원핫 벡터"로 나타내면 쓰기는 행 덮어쓰기, 읽기는 조회에 대응된다. 그래서 CPU 실행 로그를 토큰 하나씩 예측하는 일을 학습 없이 가중치 계산만으로 처리한다.

CPU 주변은 작은 호스트 프로그램이 맡는다. 화면 렌더링(PPU), 컨트롤러 입력, vblank 인터럽트(매 프레임 한 번씩 발생하는 단발 신호)는 모델 밖의 파이썬 코드가 처리한다. 체크포인트는 표준 Hugging Face Qwen3_5ForCausalLM 폴더(config.json + model.safetensors) 형식이라, 별도 로더 없이 일반 transformers로 불러올 수 있다. 파라미터는 4.67억 개, bf16으로 933MB이고 압축하면 3.3MB다.

한계도 분명하다. 매퍼 0(NROM) 카트리지만 지원하고, 공식 오퍼코드(명령어)만 쓰며, 소리(IRQ)는 없다. GitHub 스타는 235개, 언어는 Python, 코드 라이선스는 MIT다.

직접 해 본 것

저장소를 내려받아 패키지를 하나도 설치하지 않고, 인터넷이 없는 환경에서 실행해 본 기록이다.

실제로 돌린 것 — 이 저장소에는 6502를 표준 라이브러리만으로 파이썬에 다시 구현한 "참조 CPU"가 들어 있다. 모델이 아니라 순수 파이썬이라 패키지 설치 없이, 인터넷이 막힌 환경에서도 돌아간다. 이걸로 60프레임을 뽑았다.

/opt/homebrew/bin/python3 trace_frames.py ../repo/roms/full_game.nes --frames 60 --gif full_game_ref.gif --png fg

실행은 성공했고, 512×480 해상도의 PPM(픽셀 데이터 파일) 60개와 GIF가 만들어졌다. 다만 검증 스크립트로 프레임을 검사하자, 픽셀 데이터가 헤더에 적힌 크기(512×480×3 = 737,280바이트)보다 1바이트 짧다는 오류가 세 번 나왔다. 왜 1바이트가 모자라는지는 확인하지 못했다.

못 해 본 것 — "가중치가 실제로 게임을 하는" 시연, 즉 python -m nesformer run roms/thwaite.nes 같은 실제 모델 실행은 하지 못했다. README에 따르면 numba/scipy/pillow, torch/transformers가 필요한데, 이번에는 설치하지 않았고 인터넷도 막혀 있어 실행할 수 없었다.

이 맥에서 쓸 수 있나

내 환경은 Mac Studio, Apple M5 Max(arm64), 메모리 48GB, macOS 27.0.1(빌드 26A434)이고 디스크 여유는 약 160GB다. 로컬 AI 모델 서버(Splash 1.2.0)가 메모리를 약 34GB 상시 쓰고 있다.

README의 성능 수치를 보면 기본 numba 엔진은 1코어에서 초당 약 1,650토큰이고, 실제 NES보다 150~290배 느려서 NES 시간 10초가 25분쯤 걸린다. 25분짜리 CPU 연산은 이 맥에서 버틸 만하다. 하지만 34GB를 계속 쓰는 모델 서버가 떠 있는 상태에서 몇 시간씩 돌리면 메모리와 부하가 부담스러울 것 같다. hf 엔진(스톡 transformers)은 초당 약 10토큰이라 훨씬 더 느리다.

정리하면 이 맥에서 "쇼츠 한 편" 분량은 해 볼 만하지만, 풀 게임 수준의 긴 시연을 계속 돌리기는 무리다. 실제 모델 시연까지 해 보려면 인터넷이 되는 환경에서 venv(numba/scipy/pillow/torch/transformers)를 설치하고, 600프레임(≈25분) 실행이 되는지 확인하는 단계가 먼저 필요하다.

이런 분께

맞아요

  • "AI가 실제로 게임을 돌릴 수 있을까"가 궁금한 분
  • 언어모델의 내부 구조(상태·메모리 표현)가 새로운 용도로 어떻게 쓰이는지 알고 싶은 분
  • 온디바이스 소형 모델이나 신경망 기반 해석기 쪽으로 관심을 넓히고 싶은 분
  • 이 프로젝트의 GIF·화면을 직접 만들어 보고 싶은 분

안 맞아요

  • "바로 설치해서 슈퍼 마리오를 해 보겠다"는 분(설치와 ROM 라이선스 문제가 많다)
  • 게임 개발용 엔진이나 에뮬레이터를 찾는 분(데모·연구용이지 실용 에뮬레이터가 아니다)
  • 성능이 중요한 실시간 게임 시연을 원하는 분(150~290배 느리다)

주의할 점

  • 성능 — NES 시간 10초가 25분쯤 걸린다. 풀 게임을 끝까지 "모델로" 돌리기는 어렵다.
  • 해석 격리 — 화면과 소리는 가중치가 아니라 호스트 파이썬이 처리한다. "모델이 게임을 한다"는 말의 상당 부분은 실제 회로가 하는 일이 아니다.
  • 라이선스 — nesformer 코드와 가중치는 MIT(재배포·상업 이용 가능, 고지 유지)지만, 함께 들어 있는 thwaite.nes는 GPL-3.0이다. 이 ROM을 같이 배포하면 GPL 조건이 따라붙는다.
  • ROM 저작권 — nesformer는 "NROM만, ROM은 본인이 제공"하는 방식이라, 상용 게임 ROM을 상업 시연에 쓰면 별도 문제가 생긴다.
  • 기법 혼동 주의 — "NES로 컴파일된 Qwen3.5-4B"는 일반 Qwen3.5와 다른, 따로 계산해 만든 가중치다. 운영에 쓰는 모델과 헷갈리면 안 된다.
