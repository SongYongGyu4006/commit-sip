Qwen-Agent로 버그 숨긴 앱 검사, 10개 중 5개까지?

2026년 11월 3일 · 읽는 데 4분
한 줄 요약버그 10개를 숨긴 할 일 앱을 Qwen-Agent로 검사하게 했습니다. 힌트 없이는 0개, "경계 조건을 시험해 보라"는 힌트를 주자 5개를 찾았습니다. 오픈소스 에이전트 프레임워크 Qwen-Agent를 설치 없이 받아서 직접 살펴본 기록입니다.

무엇인가

Qwen-Agent는 알리바바 Qwen 팀이 만든 에이전트 프레임워크입니다. AI 모델이 지시를 이해하고, 도구를 부르고, 계획을 세우고, 기억을 쌓는 능력을 활용해 AI 애플리케이션을 만들 수 있게 해 줍니다. 문서에서 답을 찾아 말하게 하는 RAG(검색 증강 생성), 코드 실행기, 외부 도구를 연결하는 MCP, 메모리 같은 블록과 브라우저 보조·코드 실행기 같은 예제 앱이 함께 들어 있습니다. Qwen Chat의 뒤에서 돌아간다고 합니다.

라이선스는 Apache-2.0입니다. GitHub 스타는 17,242개, 저장소가 생긴 지 1,137일 된 성숙한 프로젝트입니다.

직접 해 본 것

저장소를 내려받아 인터넷 없이, 설치하지 않은 채 실험했습니다. 시험 규칙상 설치가 금지라서, 로컬 모델과 격리 폴더 안에서 명령줄 앱을 돌릴 수 있는 범위까지만 실행했습니다.

할 일 관리 명령줄 앱에 날짜 계산, 빈 입력, 한글 정렬 같은 버그 10개를 심었고, 정답 목록은 AI가 볼 수 없는 곳에 두었습니다. 그리고 "이 앱을 써 보고 이상한 점을 보고해"라고만 시켰습니다.

힌트 없이 돌리자 AI는 명령을 35번 실행하고도 진짜 버그는 하나도 찾지 못했습니다. 대신 버그가 아닌 것을 버그라고 한 오탐이 4개 나왔습니다. 도움말에 적힌 정렬·만료일 기능의 출력이 문서와 다르다며 "설계 의도와 출력이 맞지 않는 점을 버그로 판단했다"고 했습니다. 심어 둔 10개 중 발동은 시켰지만 보고하지 못한 것이 1개, 아예 건드리지 못한 것이 9개였습니다.

다음에는 "경계 조건을 시험해 보라"는 힌트를 줬습니다. 같은 앱을 다시 돌리니 찾은 버그는 5개(1, 3, 6, 8, 10번), 오탐은 0개였습니다. 힌트를 준 쪽에서 새로 발동시킨 버그는 6개(1, 3, 4, 6, 8, 10번)였고, 이 중 5개가 보고서에 올랐습니다. 4번만 발동시키고도 보고서에 담지 못했습니다.

실행에 쓴 명령은 이렇습니다(모두 종료 코드 0).

/opt/homebrew/bin/python3 scratch/agent.py baseline   # 힌트 없음, 24.8초
/opt/homebrew/bin/python3 scratch/agent.py hint hint  # 경계 조건 힌트, 46.2초
/opt/homebrew/bin/python3 scratch/chart.py            # 결과 지도, 0.1초

두 실험의 결과는 그림으로 정리했습니다. 초록은 찾은 것, 주황은 발동시켰지만 보고하지 못한 것, 회색은 아예 건드리지 못한 것입니다.

이 맥에서 쓸 수 있나

사용한 머신은 Mac Studio, Apple M5 Max(arm64), 메모리 48GB, macOS 27.0.1(빌드 26A434)이고 디스크 여유는 약 104GB입니다. 로컬 AI 모델 서버가 메모리를 약 34GB 상시 쓰고 있습니다.

Qwen-Agent 자체는 가벼운 라이브러리라 설치 부담이 크지 않습니다. 다만 48GB 중 34GB를 모델 서버가 이미 쓰고 있고 그 위에 에이전트 실행 부하가 얹히는 구조라, 여유를 미리 확인해 두는 편이 좋습니다.

확인하지 못한 것도 있습니다. 코드 실행 기능은 Docker(코드를 격리된 컨테이너에서 돌리는 기술) 샌드박스를 전제로 설계되어 있는데, 이 머신에 Docker가 있는지는 확인하지 못했습니다.

이런 분께

맞아요

  • 로컬 모델로 에이전트를 직접 돌려 보고 싶은 개발자
  • AI가 만든 코드를 품질 점검하는 용도로 써 보고 싶은 분

안 맞아요

  • 가볍게 즉석 실행을 원하는 분. 필요한 라이브러리 일부가 없으면 프로그램이 뜨지도 않아서, 설치 단계가 먼저입니다
  • Docker 없는 환경에서 코드 실행기를 원하는 분

주의할 점

첫째, 이 기록은 설치하지 않은 조건에서 본 것입니다. 실제로 붙여 쓰려면 필요한 라이브러리를 설치하는 단계가 먼저입니다.

둘째, 힌트가 결과를 크게 바꿨습니다. 힌트 없이 0개, 힌트를 주자 5개였습니다. 무엇을 시험해 볼지 분명히 말해 주느냐에 따라 결과가 달라집니다.

셋째, 오탐입니다. 힌트가 없을 때 4개, 있을 때 0개였습니다. AI가 "버그"라고 단정한 근거를 그대로 믿지 말고, 실제로 재현되는지 한 번 더 확인하는 습관이 필요합니다.

넷째, 의존성 구조입니다. 핵심 모델 관련 부분을 한꺼번에 불러오는 구조라 필요한 것만 골라 쓰기 어렵습니다. 최소한으로 설치하려면 코드를 수정(fork)해야 할 것으로 읽혔습니다.
