Craft Anything, 직접 받아서 살펴본 기록

2026년 11월 4일 · 읽는 데 5분
한 줄 요약Craft Anything은 웹사이트, 앱, 게임이 어떻게 동작하는지 내장 도구로 조사한 뒤, 코딩 AI가 원본을 본뜬 새 프로젝트를 만들고 원본과 비교하고 수정까지 해 주는 순수 Rust 기반 오픈소스입니다(8,372 stars, Apache-2.0, 2026-10-31 생성). 이 글은 저장소를 받아 설치 없이, 인터넷 없이 소스 코드를 읽고 일부 로직을 직접 돌려 본 기록입니다.

무엇인가

README에 따르면 이 도구는 4단계로 움직입니다. 먼저 Study 단계에서 원본을 살펴봅니다. 웹사이트라면 여러 화면 폭의 페이지, 코드, 파일, 실행 방식을 봅니다. 다음 Build 단계에서는 컴퓨터에 로그인된 AI 코딩 도구, 곧 코딩 에이전트가 원하는 언어와 프레임워크로 새 프로젝트를 만듭니다. Check 단계에서는 결과물을 원본과 비교해 아직 맞지 않는 부분을 나열합니다. Ready 단계에서는 결과물을 열어 돌려 보고, 수정을 요청하면 다시 다듬습니다.

모드는 두 가지입니다. 기본인 클린룸(clean room) 모드는 원본 내부(코드·파일·페이지 소스)를 전혀 읽지 않고, 방문자가 보는 것(스크린샷, 보이는 텍스트, 레이아웃, 색, 폰트)만 사용합니다. Deep 모드는 내부 코드와 파일까지 모두 읽습니다. 이 엔진은 데스크톱 앱, 명령줄, 그리고 MCP 서버(에이전트가 도구를 호출하는 표준 인터페이스) 세 곳에서 함께 쓴다고 합니다. MCP 서버는 다른 AI가 이 도구를 부를 수 있게 해 줍니다.

라이선스는 Apache-2.0(MIT 이중 선택 가능)이라 상업적 사용과 재배포가 허용됩니다. 다만 ArtCraft라는 이름과 로고는 상표라 라이선스 밖입니다. 현재 상태는 early alpha(초기 알파, 완성 전 단계)이고, README가 "작동하는 것/부분적으로만 되는 것/아직 아닌 것"을 직접 나누어 공개합니다.

직접 해 본 것

저장소를 받았지만 설치(cargo build)는 하지 않았습니다. 이 맥에 Rust 도구체인이 없어 빌드할 수 없었고, 인터넷도 없어 릴리스 바이너리나 패키지도 받을 수 없었습니다. 그래서 두 가지를 했습니다. 저장소 안의 Rust 소스를 읽으며 README가 내세우는 파싱 로직을 확인했고, 그 로직을 Python으로 옮겨 실제로 돌려 봤습니다.

Python으로 옮겨 실행한 실험은 세 가지입니다. 첫 번째는 HAR(웹사이트의 HTTP 통신 기록 파일)를 읽는 로직입니다. 리다이렉트와 에러 응답이 섞인 기록 4개를 넣고 다시 뽑아 봤고, 검증 4개를 모두 통과했습니다. 두 번째는 ASAR(Electron 앱의 자원을 묶은 아카이브 포맷)를 읽는 로직입니다. package.json을 넣었다 뺐고, index.js 파일이 원본과 바이트 단위로 일치하는지도 확인했습니다. 두 실험 모두 통과했습니다.

세 번째는 파일 형식 판별 로직입니다. 아카이브, 앱 실행 파일, AI 모델 파일 등을 마법 바이트로 구분하는데, 여기서 문제가 나왔습니다. macOS 앱 실행 파일(Mach-O) 중 여러 아키텍처가 담긴 fat 바이너리는 헤더를 바이트 순서를 뒤집어(빅엔디안) 읽어야 합니다. Rust 소스에서도 이 방식이 맞게 적용된 곳은 한 군데뿐이고, 형식 분류에 쓰이는 분기에는 잘못된 방향이 그대로 남아 있었습니다. Python 쪽에도 같은 패치를 했지만, 실행 횟수 한도에 걸려 수정 뒤 재실행까지 가지 못했습니다. 그래서 실제로 통과하는지는 확인하지 못했습니다.

하지 못한 일도 분명히 적습니다. 빌드, 테스트, MCP 서버 실행, 실제 웹사이트 재구축, 클린룸/Deep 모드 실측은 모두 하지 않았습니다. 이 맥에 Rust가 없어 빌드가 안 됐고, 인터넷이 없어 릴리스 바이너리도 받지 못했기 때문입니다.

이 맥에서 쓸 수 있나

이 글은 Mac Studio, Apple M5 Max(arm64), 메모리 48GB, macOS 27.0.1(빌드 26A434), 디스크 여유 약 105GB 환경에서 썼습니다. 로컬 AI 모델 서버가 메모리 약 34GB를 계속 쓰고 있다는 점도 참고로 적어 둡니다.

README가 밝히는 요구사항은 "Rust 1.97 이상"입니다(의존성 때문입니다). 이 맥의 Rust 버전은 확인하지 못했고, Rust 도구체인이 설치되어 있지 않다는 것만 확인했습니다. 이 프로젝트는 Rust로 빌드해야 하므로, Rust를 설치하기 전에는 바로 붙여 쓸 수 없는 상태입니다. 릴리스 패키지는 Apple silicon과 Intel을 함께 지원하는 universal 빌드로 macOS용이 제공되고, 사인·노타라이즈도 되어 있다고 합니다.

메모리 48GB가 충분한지는 판단을 유보합니다. 저장소와 README 어디에도 메모리 요구치가 적혀 있지 않습니다. 다만 로컬 모델 서버가 34GB를 계속 쓰고 있어 남는 메모리가 많지 않으니, 돌려 보려면 직접 확인해야 합니다.

이런 분께

  • 맞는 분: "이 사이트는 뭐로 만들어졌지?" 하는 궁금증을 실제로 파고들어 보고 싶은 분, 참고 구현을 분석하는 보조 도구가 필요한 개발자, Rust로 만든 내장 디스어셈블러·디컴파일러(기계어를 사람이 읽을 수 있는 코드로 되돌리는 도구)가 마음에 드는 분.
  • 안 맞는 분: 설치 몇 번으로 바로 결과물을 얻고 싶은 분(early alpha라 일부 기능이 아직 미완성입니다), 이 맥처럼 Rust가 없는데 바로 실행해야 하는 분.

주의할 점

  • 법적: README는 "소유하거나 조사 권한이 있는 소프트웨어에만 사용할 것"이라고 명시합니다. Deep 모드는 원본 코드를 실제로 읽으므로, 경쟁사 제품 같은 제3자 소프트웨어에 쓸 때는 해당 제품의 약관과 저작권 충돌 가능성을 직접 확인해야 합니다. 재구축 결과물에 원본의 로고·사진·문구를 복제하지 않도록 에이전트에게 지시가 걸려 있기도 합니다.
  • 상표: ArtCraft 이름과 로고는 라이선스 밖이라, 이 저장소를 fork해 배포할 때는 이름과 마크를 제거하거나 교체해야 합니다.
  • 성숙도: early alpha입니다. README도 일부 기능을 스스로 "partly there"라고 적어 둡니다. 로컬 모델 빌드는 "app/에 빌드할 프로젝트가 없다"에서 멈추고, 일부 도구만 시뮬레이션으로 동작합니다.
