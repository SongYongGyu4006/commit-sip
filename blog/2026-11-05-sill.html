Sill: Mac 창을 iPhone·iPad로 띄우는 오픈소스, 받아서 코드로만 시험해 봤다

2026년 11월 5일 · 읽는 데 5분
한 줄 요약Sill은 GitHub 별 4,497개, 생성 43일째인 Apache-2.0 프로젝트다(2026-11-05 04:48 KST 기준). 저장소를 내려받아 설치하지 않고 인터넷도 끊은 채 살펴봤다. 앱은 실행하지 못했고, 저장소에 들어 있는 자동 검사만 돌려 봤다.

무엇인가

Sill은 Mac의 앱 창이나 데스크톱 전체를 HEVC 영상으로 압축해 iPhone·iPad로 보내는 무료 오픈소스 앱이다. 반대로 기기에서 들어온 터치·타이핑·트랙패드 입력은 Mac의 마우스·키보드 이벤트로 바꿔 준다. HEVC는 Apple이 쓰는 영상 압축 형식이고, Sill은 Mac의 하드웨어 인코더로 이 영상을 만든다. Mac 쪽 앱은 메뉴 막대에 상주하면서 화면을 캡처하고, TLS 1.3(암호화 연결)으로 기기에 보낸다. 계정도 서버도 필요 없다. 연결은 같은 와이파이, USB 케이블, P2P 와이파이, Tailscale 같은 VPN 중 하나로만 한다.

Mac 앱과 기기 앱 모두 무료이고 광고·추적·구독도 없다. 최신 릴리스는 0.6.0(2026-11-02)이다. 저장소 문서에 따르면 서드파티 의존성 없이 Swift와 Apple 프레임워크만으로 만들었다.

직접 해 본 것

저장소만 받아 두고 설치는 하지 않았고, 인터넷도 끊었다. 시험 환경은 격리된 폴더(샌드박스)여서 시스템 파일에 쓸 권한이 없다.

그래서 앱 전체(Swift 패키지)는 빌드도 실행도 하지 못했다. swift build를 돌려 봤지만 샌드박스가 시스템 디렉터리 쓰기를 막아 실패했다. README에 나오는 --synthetic(화면 기록 권한 없이 테스트 패턴을 스트리밍하는 개발용 모드)도 같은 이유로 띄우지 못했다. 실제 기기와의 페어링은 당연히 확인하지 못했다.

대신 저장소에 들어 있는 순수 로직 검사를 돌렸다. 어떤 연결을 받을지, 클립보드를 어떻게 주고받을지처럼 앱이 스스로 판단하는 규칙의 코드를 그대로 컴파일해서 실행하는 검사다. 기기도, 화면 캡처 권한도, 네트워크도 필요 없어서 어느 맥에서든 돌릴 수 있다.

cd Tests/checks/door-policy && bash run.sh

첫 번째는 접속 정책, 즉 어떤 기기가 어떤 문으로 들어올 수 있는지 판정하는 로직을 검사한다. 결과는 ALL PASS (261), 261개 모두 통과했다.

cd Tests/checks/clipboard && bash run.sh

두 번째는 클립보드를 양방향으로 주고받는 로직을 검사한다. 결과는 340 checks, 0 failed, 실패는 없었다.

두 검사 모두 규칙 코드를 그대로 컴파일해 확인한 것이라 나름 의미가 있다. 하지만 앱이 실제로 화면을 보내는지(실기기 페어링, 영상 품질)는 확인하지 못했다. 변이 검사(코드를 일부러 망가뜨린 뒤 검사가 이를 잡아내는지 보는 방법)도 돌렸지만 420초 제한 안에 끝나지 않아 결과를 보지 못했다.

이 맥에서 쓸 수 있나

시험한 맥은 Mac Studio(Apple M5 Max, 메모리 48GB, macOS 27.0.1, 디스크 여유 약 140GB)다. 로컬 AI 모델 서버가 메모리 48GB 가운데 약 34GB를 늘 쓰고 있다.

README의 요구 사양은 "Apple silicon 또는 Intel Mac, macOS 14 이상"이다. M5 Max에 macOS 27.0.1이니 적힌 요구 사항은 충족한다. 기기 쪽으로는 실제 iPhone이나 iPad가 있어야 한다. 기기의 최소 OS 버전은 자료에 나와 있지 않다.

다만 이 맥에서 늘 켜 두기는 부담스럽다. AI 서버가 약 34GB를 차지하니 남는 메모리는 약 14GB다. README에 "기기 연결 전에는 아무것도 촬영하지 않는다"고 되어 있어 평소 부담은 크지 않을 것 같다. 그래도 격리 환경이라 앱을 실행해 보지 못했으니 실제 체감은 모른다. AI 서버가 메모리를 차지하고 있지 않은 개인 맥이라면 요구 사양 면에서는 문제없이 쓸 수 있어 보인다.

이런 분께

잘 맞는 분:

  • Mac Studio 같은 헤드리스 머신을 iPad·iPhone으로 보면서 조작하고 싶은 분
  • 계정이나 서버 없이 LAN·USB·VPN만으로 원격 화면을 쓰고 싶은 분
  • Apache-2.0 라이선스의 네이티브 Swift 코드베이스를 참고하고 싶은 분

맞지 않는 분:

  • 완전 자동화나 무인 운영에 끼워 넣으려는 분. 화면 캡처·손쉬운 사용 권한과 로그인 세션이 있어야 돌아가는 GUI 앱이라 헤드리스 운영은 안 된다.
  • 이번 주 안에 실기기 검증까지 마쳐야 하는 분. 이 글도 앱 실행까지는 확인하지 못했다.

주의할 점

  • 실제 앱 동작은 검증하지 못했다. 격리 환경에서는 샌드박스가 시스템 쓰기를 막아 Swift 패키지 전체를 빌드할 수 없었고, 그래서 화면 전송과 페어링은 확인하지 못했다. 근거는 문서와 로직 검사 결과뿐이다.
  • 가상 디스플레이(흐려 보이는 창을 기기 화면에 맞춰 따로 띄우는 기능)는 비공개 macOS API를 쓴다. README에도 "macOS 업데이트에 깨질 수 있다"고 적혀 있다.
  • 화면 캡처 권한과 손쉬운 사용(접근성) 권한이 필요하다. 다른 앱을 마음대로 제어할 수 있는 수준의 권한이니 어떤 앱에 줄지 신중하게 고르자.
  • 자료에는 예전 어느 버전에서 로컬 연결이 암호화되지 않았으니 최신 릴리스를 쓰라는 언급이 있다. 해당 버전 번호는 시험 자료에 없다. 최신 릴리스를 쓰자.
  • 릴리스와 라이선스 정보는 README 등 저장소 문서로만 확인했다. 공식 사이트, App Store, Homebrew 탭의 현재 상태는 인터넷이 막혀 있어 확인하지 못했다.
