agent-autoloop, 명령줄 AI를 백그라운드에서 혼자 일게 하는 오픈소스

2026년 11월 7일 · 읽는 데 7분
한 줄 요약Claude Code나 Codex 같은 명령줄 AI를 단말 앞에서 지키며 쓸 필요 없이, 이벤트가 오면 알아서 일하고 판단이 필요할 때만 카드로 물어보는 오픈소스 루프다. 이번 글은 이 저장소를 받아 설치 없이 코드를 읽은 기록이다.

60초 영상으로 보기유튜브 커밋 한 모금 쇼츠

무엇인가

agent-autoloop은 KKKKhazix가 만든 오픈소스다. 2026-11-03에 만들어져 약 4일 만에 스타 3,637개·포크 666개를 모은 신생 프로젝트다. TypeScript로 작성했고 MIT 라이선스다.

해결하려는 문제는 단순하다. 우리는 보통 "프롬프트 입력 → 실행 지켜보기 → 질문 대답하기"를 반복한다. 창을 닫거나 자리를 뜨면 작업은 멈춘다. 이 도구는 그 흐름을 백그라운드 루프로 바꾸는 것이다.

가운데에는 "핵심"이라 부르는 부품이 있다. 약 1,850줄이고 실행 시 필요한 외부 의존성이 0개다. 시계를 읽지 않고, 무작위를 쓰지 않고, 바깥으로 요청을 보내지 않는다. 같은 입력을 주면 항상 같은 결과가 나와야 한다는 원칙이다. 이 핵심 주변으로 네 쪽이 모두 교체 가능한 플러그인이다. 이벤트 원천(정시 작업, GitHub 이슈, HTTP 요청), 에이전트, 알림 채널, 배포(CI/CD)까지.

작업은 이렇게 돈다. ① 이벤트가 들어온다(오전 9시 정시, 새 이슈, 운영 경보). ② 규칙 파일에 따라 어떤 에이전트가 어떤 폴더에서 처리할지 정한다. 같은 주제의 새 이벤트가 줄지어 오면 한 바퀴로 병합된다. ③ 에이전트가 한 바퀴 일하고 결과를 마지막 메시지에 적고 프로세스가 종료된다. ④ 데이터 삭제, 서비스 재시작, 돈이 드는 일, 사람에게 메시지 보내기 같은 민감한 일만 사용자가 카드를 받고 판단한다. 이 기다리는 동안 에이전트는 돌지 않고 토큰도 소모되지 않는다. ⑤ 사용자가 답을 보내면 원 대화에서 이어서 작업을 끝낸다.

에이전트는 이 도구의 허브(중앙 관리 프로세스)에 딱 한 가지만 하면 된다. "결과를 마지막 메시지에 넣어라." 물어볼 일이 있으면 마지막 메시지에 특정 형식의 문단을 덧붙이면 된다. 형식이 잘못되면 같은 세션에서 그 마지막 메시지만 다시 쓰라고 하고, 다시 쓰기도 실패하면 원 결론을 유지하며 "적용하지 못했다"고 알려준다.

내장 플러그인은 네 쪽 모두 준비되어 있다. 이벤트: GitHub 웹훅, GitLab 웹훅, HTTP API, 정시 규칙. 에이전트: Claude Code, Codex, ACP, DeepSeek Harness, 일반 명령어. 채널: 데스크톱 알림(기본), Feishu, DingTalk, WeCom, Slack, Discord. 배포: PR에 라벨을 붙이면 검토 → CI 대기 → 병합 → 배포 대기 → 실서버 확인까지. 레시피로 아침 브리프, GitHub 이슈 처리, 운영 경보 대응, 사이트 상태 순회, Feishu 주간 리포트가 들어 있다.

README는 스스로 테스트 범위도 밝힌다. Claude Code, Codex, ACP는 멀티턴 질문·응답과 세션 재개를 실제로 돌렸고, Feishu는 실제 전달·버튼 콜백·카드 업데이트까지 돌렸다. 반면 Slack, Discord 등 웹훅 계열 4개 템플릿은 로컬 목(mock) 서버로만 확인했고, GitLab 웹훅은 문서의 페이로드로만 확인해 실제 GitLab은 아니다.

직접 해 본 것

솔직히 먼저, 이 저장소는 설치하지 않았다. 이번 확인의 규칙이 설치 없이, 인터넷 없이, 코드를 읽고 돌릴 수 있는 범위에서만 실행하라는 것이었기 때문이다.

그 범위에서 한 일. 저장소를 받아 코드를 읽었다. README와 패키지 설정 파일, 핵심 소스를 확인했고, 패키지 설정의 실행 시 의존성 목록이 비어 있다는 걸 확인했다. 개발용 도구만(typescript, prettier, @types/node) 있다. README가 주장한 "실행 시 의존성 0"은 사실이었다.

코드를 읽으며 확인한 것. MIT 라이선스 전문, README의 성능 표(대기 중 상태 메모리 사용 약 59.94MB), 네 가지 작동 원리(대기 중 제로 소모, 일방 기록부, 지시와 자료 분리, 반복 초과 시 재할당 중단), 에이전트가 답을 보내는 형식, 규칙 파일 형식.

실행까지 가보려 했다. 검증 명령을 돌려 보려 했으나, 반복 한도에 막혀 끝내 완료하지 못했다. 남은 흔적: 검증 명령이 약 8.8초 걸렸다는 기록은 있으나, 통과 여부는 확인하지 못했다.

그 사이 준비물까지 만들었다. 모델이나 계정 없이 응답만 출력하는 가짜 에이전트(스텁), 내 컴퓨터로만 접속되는 설정, 시뮬레이션 규칙, 테스트용 디렉터리까지. 하지만 그걸로 끝까지 돌리지는 못했다.

결론: 코드는 직접 읽어서 확인했지만, 이벤트가 오고 에이전트가 일하고 카드를 받고 답하는 흐름을 실제로 돌려 본 것은 아니다. README의 시연 예시(색 고르기)는 README에 인쇄된 예시일 뿐, 내가 받은 출력은 아니다.

이 맥에서 쓸 수 있나

이 글을 쓴 맥은 Mac Studio, Apple M5 Max(arm64), 메모리 48GB, macOS 27.0.1(빌드 26A434), 디스크 여유 약 50GB다.

README의 요구 사양은 Node 24 이상, Git, 로그인 완료된 명령줄 에이전트(클라이언트). macOS와 Linux는 추가로 curl을 쓴다. 클라우드는 필요 없고, 들어오는 포트도 없다.

사양 비교부터 하면, README가 요구 사양으로 명시한 것은 Node 24 이상, Git, 로그인된 에이전트 클라이언트, 그리고 curl(맥·리눅스)뿐이다. 램 용량, CPU 코어 수, macOS 버전을 요구 사양으로 쓴 항목은 없다. 그래서 이 맥이 그보다 "높다" "낮다"고 말할 근거가 자료에 없다. 확인 안 한 항목이다.

한 가지 참고할 숫자. README의 성능 표에 대기 중 상태 메모리 사용이 약 59.94MB라고 있다. 이 맥의 메모리 48GB에서 이 도구가 차지하는 비율은 새로 계산하지 않는다. 다만 이 맥에는 로컬 AI 모델 서버가 상시 메모리 약 34GB를 쓰고 있어, 이 도구를 그 서버 옆에 돌리면 둘이 같은 메모리를 공유하는 구조다. 로컬 모델 에이전트로 쓰게 되면 메모리 경쟁이 생길 수 있다.

이런 분께

이런 분께 맞아요:

  • Claude Code나 Codex를 쓰고, "내가 붙잡아 봐"를 반복하는 게 피곤했던 분
  • 정시 작업(아침 브리프)이나 새 이슈 처리를 에이전트로 돌리되, 민감한 일만 보고 받고 싶은 분
  • TypeScript로 된 가벼운 도구를 읽고 구조를 이해하는 게 취미인 분

이런 분께 안 맞아요:

  • 설치해서 끝까지 돌려 보고 나서 읽고 싶은 분(이번 글은 설치 없이 읽은 기록이라 실행 검증이 없다)
  • Slack·Discord에 익숙한 분(README 기준, 이 두 채널은 로컬 목 서버로만 확인했고 실제 계정까지 검증된 게 아니라는 점이 문제다)
  • "이미 2주 넘게 검증된 성숙한 도구"를 원하는 분(생성 4일차다)

주의할 점

가장 중요한 하나: 비용과 약관. 이 도구는 여러분의 로컬에 로그인된 에이전트를 직접 호출하고, 모델 사용량은 각자 계정·API 키로 계산된다. 각 벤더 약관이 해당한다. README도 스스로 "자주 돌리는 자동화에서는 API 키 사용을 권한다"며 Anthropic·OpenAI의 공식 안내를 인용한다. 개인 구독(예: Claude Pro)으로 이 자동화를 돌리면 벤더 약관 이슈가 될 수 있고, 토큰 비용도 자기 계정에 청구된다.

둘째, 검증 범위. README가 스스로 "로컬 목 서버로만 확인"이라고 밝힌 채널(Slack, Discord 등 웹훅 4종)과 "문서 페이로드로만 확인"한 GitLab 웹훅은 실제 환경에서는 다시 검증해야 한다.

셋째, 권한. 에이전트가 어떤 폴더에 읽고 쓸 권한을 갖는 건 규칙 파일이 정한다. 이 파일이 어디에 있고 누가 바꿀 수 있는지를 정하는 게 사용자의 몫이다.

넷째, 카드 링크. 카드가 웹 링크로 열리면 그 링크를 눌러 답하는 구조다. 로컬에서만 열면 안전하지만, 인터넷으로 열면 공격 표지가 넓어진다. 지금 설정은 127.0.0.1로만 열리도록 하는 게 기본이다.

다섯째, 성숙도. 생성 4일, 스타 3,637. README가 스스로 밝힌 테스트 한계(예: 전원이 꺼지는 상황은 따로 못 검증)를 그대로 읽자.

여섯째, 이 글의 한계. 설치하지 않았으므로 실행 검증은 없다. "직접 해 본 것" 절은 코드 읽기 수준이다.
