로컬 AI개발 도구

프롬프트를 다윈 진화로 자동 고쳐주는 오픈소스, 설치 없이 받아서 돌려 봤다

2026년 11월 13일 · 읽는 데 4분
한 줄 요약imbue-ai/darwinianevolver는 다윈 진화 아이디어를 코드로 옮긴 가벼운 오픈소스다. 프롬프트가 실패한 사례를 LLM에게 보여 주고 고쳐 쓰게 한 뒤, 점수가 더 좋은 쪽을 남기는 방식이다. 저장소를 내려받아 설치 없이 코드를 읽었고, 내 로컬 모델로 진화 루프를 한 세대 실제로 돌려 봤다.

무엇인가

"organism(개체)"을 떠올리면 이해가 쉽다. 이 도구는 개선하려는 프롬프트나 코드 조각을 하나의 개체로 본다. 반복마다 세 단계를 거친다. 유망한 부모를 고르고, LLM이 실패 사례를 보고 변이를 만들고, 그 결과를 수치 점수(여기서는 오류 수)로 평가한다. 점수가 좋은 쪽이 다음 세대로 넘어간다.

옵션으로 "배치 변이"와 "학습 로그"가 있다. README는 변이가 20%만 성공해도 진화가 이어진다고 설명한다. 학습 로그는 지난 세대에서 시도한 변이와 결과를 다음 세대에 넘겨서 같은 실수를 되풀이하지 않게 해 준다. 저장소에는 parrot(README 예시), multiplication_verifier, ARC-AGI-1/2 같은 예제 문제가 들어 있다.

직접 해 본 것

저장소를 받아서 시스템 패키지를 건드리지 않는 격리 폴더에서 시험했다. 규칙은 세 가지였다. 설치하지 않는다. 인터넷을 쓰지 않는다. 코드를 읽고, 돌려 볼 수 있는 것만 돌린다.

먼저 의존성을 확인했다. 시스템 Python 3.9로 필요한 패키지를 점검해 보니 필요한 라이브러리가 하나도 없었다. 게다가 저장소가 요구하는 Python 버전도 내 맥에 있는 3.9로는 맞추기 어려웠다. 그래서 3.14로 격리 환경을 만들고, 로컬에 이미 캐시된 패키지만 가져다 썼다.

그 환경에서 진화 루프를 한 세대 돌렸다. 대본 3줄을 쓰게 하는 지시문(프롬프트) 2개를 부모로 두고, 변이를 1회 거친 뒤 검사 오류가 줄어드는지 봤다.

$ PYTHONPATH=repo venv/bin/python scratch/evolve_shorts.py run
RESULT initial_errors=8 best_errors=5 children=2
IMPROVED=yes

오류는 8개에서 5개로 줄었다. 종료 코드는 0이었고 26.3초 걸렸다.

$ PYTHONPATH=repo venv/bin/python scratch/evolve_shorts.py selftest
SELFTEST good_errors=0 bad_errors=5
SELFTEST ok

두 번째는 모델 없이 검사기만 확인한 시험이다. 정상 대본에서는 오류가 0개, 일부러 틀리게 쓴 줄에서는 오류가 5개 나오는지 봤고, 0.1초 만에 통과했다.

못 해 본 것도 있다. 저장소 기본 예제(parrot)의 라이브러리 루프는 실행 기록이 없다. 이 예제에 필요한 LLM 서버가 시험 환경에 떠 있는지 확인하지 못해서, 스크립트만 만들어 두고 돌리지는 않았다. 그러니 "예제까지 문제없이 돌았다"고는 말할 수 없다.

이 맥에서 쓸 수 있나

내 맥 사양은 이렇다. Mac Studio, Apple M5 Max, 메모리 48GB, macOS 27.0.1, 디스크 여유 약 110GB. 여기에 메모리를 약 34GB씩 늘 쓰는 로컬 AI 모델 서버가 떠 있다.

저장소가 요구하는 Python 버전은 맥 기본 Python 3.9와 맞지 않는다. 그래서 3.14로 격리 환경을 따로 만들고, 로컬에 캐시된 패키지만 넣어서 시험했다. 3.9에서 바로 돌릴 수는 없고 다른 버전으로 환경을 따로 꾸려야 한다는 점은 실제로 쓰기 전에 짚고 넘어가야 한다.

메모리는 넉넉했다. 48GB 중 로컬 모델 서버가 약 34GB를 늘 차지하는데, 그 위에 격리 환경을 올려도 문제가 없었다. 실제 변이는 로컬에서 돌린 27B급 모델(74-92 tok/s)이 맡았다. 내 맥에서 일단 돌려 보는 것 자체는 어렵지 않다는 얘기다. 다만 변이가 20%만 성공해도 진화한다는 README 설명은 큰 LLM을 전제로 한 것이고, 27B 모델이 만든 변이의 품질은 이번 시험으로는 확인하지 못했다.

이런 분께

맞아요 — 프롬프트를 손으로 계속 고쳐 가며 다듬는 사람. 문서 검사, 심사, 대본처럼 실패 사례가 쌓이는 업무에 "알아서 고쳐 주는" 루프를 붙이고 싶다면 바로 써 볼 만하다. 저장소가 요구하는 Python 버전의 격리 환경과 변이를 맡을 LLM(클라우드 API든 로컬 모델이든)만 있으면 된다.

안 맞아요 — AGPLv3 라이선스가 신경 쓰이는 사람. 이 저장소는 strong-copyleft라서 서버로 운영하면 소스 공개 의무가 생길 수 있다. 법적 요건까지 이번에 확인한 건 아니니, 상용 서비스에 넣기 전에는 따로 확인해야 한다. "완제품"을 기대하는 사람에게도 맞지 않는다. 평가 함수와 변이 규칙 같은 문제 정의는 직접 짜야 한다.

주의할 점

라이선스는 AGPL-3.0이다. 내부 실험용이라면 부담이 없지만, 네트워크 서비스로 내놓는 순간 소스 공개 문제가 생길 수 있다. 상용으로 쓰기 전에 확인하자.

변이를 맡은 LLM에 따라 결과가 흔들릴 수 있다. 27B급 로컬 모델이 프롬프트를 얼마나 잘 고쳐 쓰는지는 이번 시험에서 확인하지 못했다. 오류가 줄었으니 성공은 성공이지만, 그 변이가 정말 "나아진" 것인지는 대상을 바꿔 가며 더 봐야 한다.

Python 버전도 잊지 말자. 3.9 시스템에서는 바로 돌아가지 않으니 격리 환경을 따로 만들어야 한다.
