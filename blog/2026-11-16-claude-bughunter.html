Claude-BugHunter 직접 돌려보기 — Claude Code를 버그헌터처럼 만드는 오픈소스

2026년 11월 16일 · 읽는 데 7분
한 줄 요약버그헌터가 쌓아 온 스킬 83개와 검증 도구 묶음을 설치 없이 받아 실제로 돌려 봤다. 직접 재 보니 "7-Question 검증 게이트"는 결국 문구를 검색하는 수준에 그친다.

무엇인가

Claude-BugHunter는 Claude Code(터미널에서 돌아가는 AI 코딩 에이전트)에 "스킬"을 끼워 넣어 시니어 버그헌터처럼 움직이게 만드는 오픈소스다. (별 7,102개, 포크 1,081개, MIT 라이선스, 약 6개월 전 공개)

여기서 "스킬"은 AI 에이전트가 주제에 맞춰 알아서 꺼내 쓰는 지식 문서(마크다운 파일)다. 이름을 직접 부르지 않아도 "acme.com 테스트해줘"라고 쓰면 관련 스킬이 로드된다.

구성은 4가지다.

  • 83개 스킬: XSS·SQLi·IDOR(다른 사람의 식별자로 그 사람의 데이터에 접근하는 공격) 같은 웹앱 취약점 탐지 스킬이 58개다. 여기에 M365/Okta/vCenter 같은 기업 플랫폼 공격 체인, 리포트 작성·증거 위생, 정찰, 방법론 스킬이 더해진다. 취약점 스킬은 HackerOne에 공개된 리포트 681개에서 뽑아냈다.
  • 15개 슬래시 커맨드 + cbh CLI: cbh는 터미널에서 바로 돌리는 정찰/분류/검증/리포트 실행기다. 외부 의존성이 0개(파이썬 표준 라이브러리만 사용)라서 설치 없이 실행된다.
  • 7-Question 게이트: 리포트를 내기 전에 7가지 질문(범위 안의 자산인가, 증거가 있는가 등)을 통과해야 하는 검증 규칙이다.
  • 4단계 구조: 방법론 → 웹앱 취약점 탐지 → 기업 인프라 공격 → 리포트·증거 순서로 이어진다.

내부 Active Directory(윈도 도메인) 공격, C2(악성 소프트웨어 지령 통신) 프레임워크, 포스트익스플로이트(침입 후 활동)는 일부러 뺐다. 대상은 외부 인터넷 표면뿐이다.

직접 해 본 것

저장소는 받았지만 설치는 하지 않았다. 인터넷이 없는 환경이라 의존성이 0개인 스크립트만 골라 돌렸다.

1. 분류 (classify): 버그를 찾은 것처럼 보이는 URL을 넣어 봤다.

python3 scripts/cbh.py classify "https://api.acme.com/v1/users/42?next=https://evil.com"

→ API 오류, IDOR, SSRF(서버가 임의 주소를 대신 탐색하게 만드는 공격) 스킬 3개가 매칭됐다. 각 스킬 문서 경로와 다음 단계도 알려 줬다. 제대로 작동했다.

2. 검증 게이트 (triage): 시나리오 3개로 7-Question 게이트를 시험했는데, 여기서 핵심 한계가 드러났다.

  • (a) 7가지 질문 중 4개만 답한 문장 → KILL — failed Q4,Q5,Q6 (정상)
  • (b) 실제 증거가 있는 발견인데 "behavior not documented"라는 표현만 쓴 문장 → 잘못 KILL (위양성)
  • (c) "first reported", "leaked PII", "oob callback" 같은 문구만 넣은 문장 → PASS (위음성)

결국 게이트는 질문의 *내용*을 판단하지 않고 문구를 검색한다. 증거가 있어도 해당 문구가 없으면 거부하고, 문구만 있으면 통과시킨다.

3. 리포트 (report)

python3 scripts/cbh.py report finding-idor4.md --platform bugcrowd --out report-draft.md

→ Bugcrowd(버그바운티 플랫폼) 리포트 템플릿이 제대로 만들어졌다. 심각도 요청, 채울 슬롯, 계정 위생 지침이 들어 있다. 현재 작업 폴더 밖 경로에 쓰려고 하면 거부한다.

4. 스킬 린트: 스킬 83개를 모두 검사했더니 에러 0, 경고 11이 나왔다. 경고는 전부 "본문 500줄 초과"였고, 정찰 스킬 하나는 1,640줄이나 됐다. 이걸 자동으로 로드하면 토큰 비용이 꽤 들겠다.

못 해 본 것 (사유 그대로)

  • 정찰: 실제 HTTP 요청이 필요해서 인터넷 없이는 불가
  • Burp MCP, /hunt 엔진: Claude Code 전용이고 LLM이 필요
  • 에이전트에 스킬 실제 설치: 그 자체가 "다음 단계"라 이번엔 생략

이 맥에서 쓸 수 있나

내 환경은 Mac Studio, Apple M5 Max, 메모리 48GB, macOS 27.0.1, 디스크 여유 약 129GB다. 로컬 AI 모델 서버가 메모리를 약 34GB 상시 쓰고 있다.

항목내 사양이 도구
OSmacOS 27.0.1macOS·Linux·Windows 지원
CPUM5 Max (arm64)Python 스크립트, ARM 문제없음
RAM48GB (AI 모델 서버 34GB 상시)cbh CLI는 의존성 0으로 가볍다
디스크여유 약 129GB스킬 83개 합계 약 2.1MB

사양만 보면 모두 넉넉하다. cbh CLI는 의존성이 0개(파이썬 표준 라이브러리만)라 따로 설치하지 않고도 돌아갔다. 다만 큰 전제가 하나 있다. 이 스킬 묶음은 원래 AI 에이전트(Claude Code 등)에 얹어 쓰도록 만들어졌다. cbh CLI만으로는 분류·검증·리포트까지만 되고, "AI가 취약점을 찾아낸다"는 핵심 가치는 에이전트가 없으면 누릴 수 없다.

로컬 LLM 환경이라면 이렇다.

  • 스킬 83개를 전부 자동 로드하면 토큰 부담이 크다. 약 2.1MB짜리 문서를 매번 읽히는 셈이다.
  • 로컬 모델이 이 공격 스킬들을 안정적으로 수행하는지는 확인하지 않았다. 이번 시험에서는 LLM 에이전트로 실행할 수 없었다.
  • 부분 적용이 현실적이다. LLM/AI 기능 검증 스킬과 증거 위생 스킬, 이렇게 2개만 골라서 "내가 로컬 AI로 만든 기능은 안전한가"를 따지는 검증 기준으로 쓰면 된다.

이런 분께

맞아요

  • Claude Code로 버그 헌팅이나 외부 레드팀을 하는 분 (정찰부터 리포트까지 전 단계 보조)
  • 자신의 LLM/AI 기능(채팅·RAG(문서 기반 질답)·에이전트) 보안을 점검하고 싶은 분. 이 묶음의 검증 규율은 "2회 실행해서 재현되는가, 외부 콜백이 없으면 발생하지 않은 것, 모델이 헛것을 본 건 발견이 아니다"이다. 로컬 LLM으로 AI 기능을 만드는 사람에게도 그대로 들어맞는다.
  • 리포트 작성과 증거 위생(쿠키·개인정보 가림 처리) 규율이 필요한 분

안 맞아요

  • 내부 네트워크·C2·포스트익스플로이트를 다루는 분 (일부러 뺀 영역)
  • "AI가 대신 공격해 준다"고 기대하는 분. 스킬은 지식 문서일 뿐 자율 에이전트가 아니다. 판단은 여전히 사람 몫이다.
  • 토큰 비용에 민감한 환경. 스킬을 전부 자동 로드하면 비싸다.

주의할 점

  1. 검증 게이트 = 키워드 매칭 (위 실측 참고). LLM 판단을 함께 쓰지 않으면 "증거 있는 발견은 KILL, 문구만 갖춘 허위 발견은 PASS"가 된다. 이 게이트 하나만 보안 관문으로 믿고 쓰지 마라.
  2. 권한: 스킬에는 공격 페이로드, CVE 체인, OSINT 수법이 들어 있다. "자기 소유이거나 서면 허락을 받은 자산만"이라는 규정이 문서에 있긴 하지만, 스킬은 늘 로드되는 구조다. 세션마다 허락받은 작업이라는 맥락을 다시 알려 줘야 한다.
  3. 범위: 외부 인터넷 표면에 한정된다. "우리 스택 전체 보안 감사"를 기대하면 안 된다.
  4. Anthropic 런타임: Claude 모델의 실시간 사이버 보호 기능이 "취약점 이용·공격 도구 개발"을 기본으로 막는다. 허용된 정당한 작업도 거절당할 수 있다. 이런 경우를 위한 공식 경로(무료 인증 프로그램)가 따로 있다. 이 묶음 자체의 문제는 아니다.
  5. 라이선스: 코드는 MIT, 스킬 문서는 CC BY 4.0이다. 상업적으로 쓸 수 있고, 재배포할 때는 출처를 표시하고 원 저장소 링크를 달아야 한다.
